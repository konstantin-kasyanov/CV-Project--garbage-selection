# Детекция отходов на сортировочном конвейере

Проект по обнаружению и классификации отходов на изображениях для соревнования Renue на Kaggle. Модель находит каждый объект, определяет один из 15 классов и возвращает координаты рамки с уверенностью предсказания.

**Лучший результат: 0.89152** — ансамбль YOLO11s и YOLO11m с TTA и Weighted Boxes Fusion.



## Данные

Датасет содержит 9000 JPEG-изображений размером 2048 × 1486 пикселей: 6001 размеченный кадр и 2999 тестовых. На одном кадре может быть несколько объектов или не быть ни одного.

Исходные файлы:

- `images/` — изображения;
- `train.csv` — отдельная строка для каждого объекта: имя файла, рамка `[x_left, y_top, width, height]` в пикселях и `category_id`;
- `test.csv` — имена тестовых изображений;
- `sample_submission.csv` — пример формата отправки.

Классы включают разновидности PET, PND, прочий пластик и непластиковые отходы. Исходные номера классов — 1–15; для обучения YOLO они преобразуются в 0–14. Пустой кадр получает пустой файл разметки.

Данные нужно получить у организатора и разместить локально. Изображения, веса и результаты запусков не входят в исходный код проекта.

## Решение

Эксперимент проходит последовательно:

1. Проверка структуры данных, распределения классов и рамок на изображениях.
2. Преобразование разметки в формат YOLO и разделение изображений на train/validation в пропорции 80/20 с `seed=42`.
3. Короткий замер скорости и обучение YOLO11s на 50 эпохах при `imgsz=960`.
4. Проверка разрешения при инференсе и дополнительное обучение YOLO11s от выбранных весов на 100 эпохах с меньшим learning rate.
5. Обучение YOLO11m на 100 эпохах на том же разбиении.
6. Проверка TTA и ансамбля моделей через WBF на validation.
7. Формирование предсказаний для теста и итогового CSV.

Модели начинают обучение с предобученных весов. Физический batch равен 16 для YOLO11s и 8 для YOLO11m. Для сохранения цветовых признаков отключено изменение оттенка (`hsv_h=0`). Остальные параметры каждого этапа явно заданы в скрипте обучения.

TTA использует преобразованные версии кадра при инференсе. WBF объединяет пересекающиеся рамки одного класса, учитывая уверенность моделей. В итоговом решении использованы одинаковые веса моделей в ансамбле и порог IoU 0.65.

Трекинг и присвоение ID объектов не используются: соревнование оценивает детекцию на отдельных изображениях.

## Метрика

Для каждого класса рассчитывается AP по порогам IoU от 0.50 до 0.95 с шагом 0.05. Затем значения усредняются с весами по числу размеченных объектов класса:

```text
weighted_mAP = sum(AP_class × object_count_class) / sum(object_count_class)
```

Метрика учитывает правильность класса, полноту обнаружения и точность локализации. Частые классы сильнее влияют на итоговый результат.

Во время обучения `metrics.py` вычисляет weighted mAP по результатам валидации Ultralytics, записывает историю в `weighted_metrics.csv` и сохраняет лучший checkpoint как `best_weighted.pt`. Встроенный `best.pt` выбирается по критерию Ultralytics и может соответствовать другой эпохе. Для следующих этапов используется `best_weighted.pt`.

Модель обучается по функции потерь YOLO. Weighted mAP применяется для оценки и выбора весов.

Для сравнения отдельных моделей и WBF используется TorchMetrics на одном validation-наборе с одинаковым лимитом 100 детекций на кадр. Числа этого расчёта могут отличаться от валидации Ultralytics, поэтому варианты сравниваются внутри одной реализации метрики.

## Результаты соревнования

| Решение | Public score |
| --- | ---: |
| YOLO11s, 960 | 0.88094 |
| YOLO11s, 960, TTA | 0.88399 |
| YOLO11m, 960, TTA | 0.88388 |
| YOLO11s + YOLO11m, TTA, WBF IoU 0.65 | **0.89152** |

Это результаты отправок исходного эксперимента. Они приведены для описания проекта; повторный запуск тетрадки формирует собственные результаты. Public score рассчитан на публичной части теста и не является оценкой на всём тестовом наборе.

## Окружение

Исходный эксперимент выполнен на Windows с NVIDIA GeForce RTX 4070 SUPER 12 ГБ, Intel Core i5-12600 и 32 ГБ RAM.

Использованное программное окружение:

- Python 3.13.14;
- PyTorch 2.11.0+cu128;
- Ultralytics 8.4.164;
- pandas, NumPy, Pillow, Matplotlib, scikit-learn;
- TorchMetrics, faster-coco-eval и ensemble-boxes.

Зависимости проекта перечислены в `requirements.txt`. CUDA-сборка PyTorch устанавливается отдельно.

## Запуск

Разместите в корне проекта `waste_detection_experiments.ipynb`, `requirements.txt`, `train.csv`, `test.csv` и папку `images/`. Папка изображений должна называться именно `images`, чтобы YOLO находил соседнюю папку `labels/`.

Создайте окружение и установите зависимости в PowerShell:

```powershell
py -3.13 -m venv .venv
.venv\Scripts\python.exe -m pip install torch==2.11.0 torchvision --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Откройте тетрадку в VS Code и выберите `.venv` как Jupyter kernel. Рабочая директория kernel должна совпадать с корнем проекта. При первом запуске предобученные веса YOLO загружаются через интернет, если их ещё нет локально.

Первый проход тетрадки создаёт самостоятельные скрипты рядом с ней:

| Скрипт | Назначение |
| --- | --- |
| `prepare_data.py` | Разметка YOLO, train/validation split и конфигурация датасета |
| `metrics.py` | Weighted mAP и сохранение лучших весов |
| `train.py` | Замер скорости и этапы обучения |
| `resume_train.py` | Аварийное продолжение прерванного обучения |
| `evaluate.py` | Валидация модели |
| `predict.py` | Предсказания на тесте |
| `ensemble.py` | Проверка WBF и сборка итогового CSV |

Все длительные операции закрыты флагами `RUN_* = False`. Включайте нужный флаг и выполняйте соответствующую ячейку по мере продвижения по эксперименту. После изменения настроек повторно выполните ячейку настроек.

После сравнения базовой и дообученной YOLO11s выберите `S_WEIGHTS`. После проверки ансамбля задайте `SELECTED_WBF_IOU`. По умолчанию выбор порога отсутствует, поэтому итоговый CSV не создаётся случайно.

Ячейки генерации скриптов можно удалить после первого выполнения. Ячейки вызовов продолжат работать с созданными файлами. Генератор не перезаписывает существующий скрипт, если его содержимое отличается.

## Файлы результатов

- `labels/`, `train_images.txt`, `val_images.txt`, `garbage.yaml` — подготовленные данные;
- `runs/` — веса, история метрик и отчёты обучения;
- `reports/` — результаты валидации и сравнения ансамблей;
- `submission_s_tta.csv`, `submission_m_tta.csv` — предсказания отдельных моделей;
- `submission_wbf.csv` — итоговый ансамбль.

В submission одна строка соответствует одному имени из `test.csv`. Поле `bbox` содержит список объектов `[category_id, confidence, x_left, y_top, width, height]` с координатами в пикселях. Для кадра без объектов записывается `[]`. Кавычки вокруг списка в CSV необходимы для корректного хранения запятых внутри поля.

## Продолжение после сбоя

Аварийный скрипт не вызывается тетрадкой автоматически. Например, для прерванного дообучения YOLO11s:

```powershell
.venv\Scripts\python.exe resume_train.py --run-dir runs\yolo11s_960_finetune_100ep
```

Нужны `last.pt`, `best_weighted.pt` и история `weighted_metrics.csv` в папке запуска. Скрипт восстанавливает состояние обучения и исторически лучший weighted checkpoint. Незавершённая эпоха выполняется повторно. Обычный запуск обучения защищён от повторного использования уже существующей папки запуска.

## Ограничения оценки

Разбиение выполняется по изображениям. На последовательных кадрах могут присутствовать одни и те же объекты, поэтому случайный split способен завышать оценку переноса на новую съёмку. В исходных CSV нет идентификаторов видеосессий для группового разбиения.

Фиксированный seed помогает воспроизводимости, но не гарантирует одинаковые результаты при смене оборудования, версий библиотек или условий запуска. Для применения на производстве потребуется отдельная проверка на новых видеосессиях и условиях съёмки.
